# 写东西的规矩与工具链

主文档（`SKILL.md`）是**门禁**（最贵的几条上桌）；本文件是它的**细则** —— 按主题展开，按需读。

## 一、写东西的规矩

- 内部文档用中文；`README.md` 首屏与 npm 包 README **中英兼顾**。
- **不要写"已验证 / 已对齐 / 应该没问题"，除非同一条里给了可复现的命令或输出**；
  不要把"没做过"说成"做过" —— 没证据就写"**未实测**"，并说清怎么才能测。
- 踩过的坑写进 `docs/FINDINGS.md`，**带真因与解法**，不要只写现象；
  结论被推翻要**留痕**，不要悄悄改掉。
- 数字（版本、分数、项数）只写在 `docs/STATUS.md`，别处一律给**指针**。

## 二、写带工具链的代码时

- **查 MoonBit API 用 `moon ide`，别 grep 标准库**：

```bash
moon ide doc "String::*rev*"    # 精确列签名
moon ide outline <file|dir>     # 结构骨架
moon ide peek-def <symbol>      # 定义 + 上下文
```

- 工具链正从 Python 迁到 MoonBit：`tools/mbtools/` 是**独立嵌套模块**（不污染库的 `moon.mod`），
  经 `bash tools/mb.sh <子命令>` 调用。
  迁移规矩：**新实现必须与旧实现逐行对账**（两边都有 `--mode list`），并做**证伪测试**
  （塞诱饵 → 必须点名 + **非零退出**）。出处 `AGENTS.md` §2。
- 新增 / 改动验证脚本时，"**验证脚本要能识别我拿到的是不是这次的**"是**硬要求**：
  无条件相信返回值、或让产物无法自证新鲜，都会产出**读数真实但结论错误**的报告（`AGENTS.md` §4）。
