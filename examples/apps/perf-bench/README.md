# perf-bench —— 性能基准负载（**仪器，不是示例**）

> 这一份不是"又一个 demo"。它是 [`PLAN.md` §4.1](../../../PLAN.md) 里 **D1** 要的那个
> "可控规模的长列表"，仪器在 [`tools/perf_bench.mjs`](../../../tools/perf_bench.mjs)，
> 数字落在 [`docs/PERF.md`](../../../docs/PERF.md)。

## 1. 一句话

**N 行列表，N 由宿主在挂载前注入** —— 于是"改前 / 改后"量的是**同一份产物**（同一个哈希）。
规模写死在代码里的话，两次测量之间隔了一次重编，编译差异会混进读数。

```bash
# 仓库根
node tools/perf_bench.mjs --n 100,1000,5000 --mode translate     # 翻译层（A/B 看这档）
node tools/perf_bench.mjs --n 1000 --mode dom                    # 真 React + jsdom（整条 Web 帧）
node tools/perf_bench.mjs --n 5000 --profile                     # 这些毫秒花在谁身上
```

## 2. 负载形状（**口径**：改它必须同步改仪器与 `PERF.md`）

```
div(root)                                  1 个元素
  ├ div(header)
  │   ├ span("perf-bench N=… tick=…")      每帧文本都变 ⇒ React 必须真重渲
  │   └ button("+1")  on_click=emit(Tick)  ★ 仪器靠它驱动帧（文本 `+1` 是接口）
  └ div(list)
      └ N × div(row)
            ├ span(长中文文本)              真实的文本节点
            ├ span(id)
            └ button("·") on_click=emit(Bump)  每行 1 个 handler
```

**每行 4 个作者元素**（`div` `span` `span` `button`），但树上是 **7 个** ——
因为 `render.mbt` 会把**每个文本节点再包一层 `Text`**（RN 的硬约束：裸字符串不能当 `View` 的子节点）。
所以**理论元素数 = 7N + 7**，仪器每次都断言这个数（`shape_ok`）：
负载形状一变，它立刻红，而不是让你拿两份不同负载的读数去比。

## 3. 它为什么必须存在（而不是拿现有的示例凑）

| 想要 | 为什么现有示例给不了 |
|---|---|
| 规模作为**自变量** | 示例的规模是写死的；改规模 = 改代码重编 = 两次测量的产物不同 |
| **每帧**成本 | 示例只在交互时才重绘；基准要在"同一个负载上连跑几百帧" |
| 成本**归因** | 需要一个"既有文本、又有样式、又有 handler"的稳定混合，三个嫌疑点才都覆盖到 |
| 可复现 | 一条命令、零 Metro、零浏览器、零模拟器 —— 所以它能当成门跑 |

## 4. 边界（**别把这里的数字读成"手感"**）

仪器文件头写了五条，这里再钉一遍最容易误读的三条：

1. **没有布局**：node 里跑，jsdom 不做布局、Yoga 不在。真机掉帧里很大一块是布局与绘制 ——
   那要 Chrome Performance / `adb shell dumpsys gfxinfo`（D2 原文）。
2. **没有原生渲染**：Android 那半一点没碰。
3. **调度是同步的**（`scheduleTask`/`scheduleFrame` 直接调用）：量的是"算完这一帧要多少计算"，
   不是"调度器什么时候轮到它"。所以这组数字**天然是下界** —— 真机只会更差。
4. 引擎是 V8（node），真机是 Hermes/JSC：**常量会差，曲线的形状才可迁移**。

## 5. 纪律

- **不带 `--trials` 的读数不足以支持"优化有效"**：进程间方差能吞掉 20% 的差
  （本轮就被吞过一次）。仪器会打噪声带。
- 两次读数要**比对产物哈希**（仪器会打）。哈希不同 = 不是同一份产物，曲线不可比。
- A/B 用 `--artifact <文件>` 量两份**留档的构建**，不要在测量中途重编 ——
  重编既会换掉产物，也会用掉 CPU 把计时搅乱。
