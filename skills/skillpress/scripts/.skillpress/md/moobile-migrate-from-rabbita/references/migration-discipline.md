# 迁移纪律：不许自作聪明

主文档（`SKILL.md`）是**门禁**（最贵的几条上桌）；本文件是它的**细则** —— 按主题展开，按需读。

## 一、负面清单

| 不做 | 为什么（原文在 `npm/moobile-host/lib/migrate/create.js` 文件头 / `docs/design/SCAFFOLD.md` §3.7.4 / `docs/plan/PLAN-yi-port-2026-10.md` §7） |
|---|---|
| 不重写业务逻辑 | `update` / `view` 的结构、数据模型、文案**一个字都不猜着改** |
| 不"顺手删掉"迁不过去的代码 | 整块用 `// ` 注释掉并留 `TODO(migrate)` 头；决定权留在人手上 |
| 不承诺"迁移后效果一致" | RN 的排版与浏览器不同，效果要**重新验** |
| 不猜运行时算出的类名 | `class=some_var` 一个字符都不动，记成 TODO（猜错的代价是把错样式埋进用户代码） |
| 不改宿主之外的工程配置 | `app.json` 的图标 / 包名等仍是模板默认值（报告 §6 自己写着这条） |
| 不把"未知"当去向 | 报告里**每一行都必须指得出下一步** |

> **判据是"报告零遗漏"，不是"自动改对了多少"。** 所以每一处自动改写都必须说得出它依据的是哪条
> **可判定**的事实（CSS 规则原文、源码里的祖先链、类的字面量）；判不了的一律进 TODO。

## 二、三类"算账"断言（这份报告为什么可信）

- **样式层**：`声明总数 = 已映射 + 有损`，**不闭合就抛**（`style-emit.js` 的硬断言）。
  有损不是"忘了做"，是 `@style` **明确不表达**（grid / sticky / transform / box-shadow / 伪类…）。
- **源侧账本**：每一条源 CSS 声明恰好落进一个**有名字的桶**；"算成已映射却没有调用、也没有说明"的
  （`silentEmpty`）在真实应用上**必须是 0**。
- **一个类一条声明都没映射成功时，函数照样生成**（返回空 `Style`）并带 `TODO(migrate)`：
  删掉调用点会让界面**静默变空**，留个空样式只是"没样式"，而且报告里**点得出名字**。

## 三、什么自动改、什么必须留给人

| 动作 | 依据 | 谁做 |
|---|---|---|
| `using @rabbita {…}` → `using @html {…}`（去掉 `type Val`） | 两边的包对应关系 | 自动 |
| `fn app() -> Val[Html]` + `fn main` → `pub fn app() -> @moobile.JsValue` | TEA 的 `update` / `view` 签名两边一致；有 init 就用 `handlers_with_init` | 自动 |
| `moon.pkg` 的 import 映射、`moon.mod` 换依赖、目标收敛 `+js` | `IMPORT_MAP` 表 | 自动 |
| `class="a b"` → `attrs=@styles.att(@styles.…)`；条件类 → `attrs=if c {…} else {…}` | 类的**字面量** + 祖先链上下文键 | 自动 |
| `moon.pkg` 补 `@styles` / `@moobile` import、去掉 `pkgtype(kind:"executable")`、入口包挂 `link.exports` | 改完的文本里到底用没用到 | 自动 |
| `class=some_var`、同一元素已有 `attrs=`、类名查无规则 | **判不了** | 人工（进 TODO） |
| `@dom.*`、`extern "js"`、标签表外的标签、`on_click` 挂在 `div` / `span` / `p` 上 | 见主文档的实测教训 | 人工（桩 / 注释 / 换标签） |
| 没登记的 rabbita import | 不猜，**原样保留并点名**（它多半编不过） | 人工 |

> `class=` 这条最容易被低估：它在 moobile 里**能编译**（签名里还留着 `class?`），
> 但**没有任何视觉效果** —— 能跑、不报错、只是没样式（`class-rewrite.js` 文件头）。

## 四、迁不过去的代码：保底桩优先，整块注释是下策

可判定的事实："这块里有没有一个**签名本身可迁移**的函数定义。"

- **有 ⇒ 保底桩**：签名照原样（调用点一个字不用改），函数体给一个空值
  （`Html` → `nothing`、`Unit` → `()`、`Bool` → `false`、`Cmd` → `@cmd.none`…），
  拿不到合适空值才 `abort("TODO(migrate): …")`，**原实现以注释保留在下面**。
- **没有 ⇒ 整块注释**：连签名都迁不过去（参数类型带 `@dom`、或根本不是函数定义，
  如 `extern "js" fn … = "…"`），留着只会把编译错误传给使用者。
- 一律注释**为什么是错的**（**实测**）：`view` 调 A、A 里有 canvas ⇒ A 被注释 ⇒ `view` 编不过也被注释
  ⇒ 入口也被注释，**生成物根本挂不起来**，而**报告里看不出来**。
- 桩体为什么不一律 `abort`（也是实测）：返回 `Html` 的函数挂在列表页里，`abort` 会变成
  **整页白屏**，用户看到一条与迁移无关的 panic；给空值才是"其余部分照常渲染，缺的那块有 TODO 点名"。
- 整块注释**设计上会传播**（引用了被注释块里定义的名字的块也一起被注释，迭代到不动点）；
  ⚠️ **但这一轮传播实测不生效** —— `create.js` 里那行正则的 `\b` 写在模板字面量里，
  是**退格符**而不是词边界，**从不命中**。所以遇到这种引用，编译会真的报错，按**人工**处理。
