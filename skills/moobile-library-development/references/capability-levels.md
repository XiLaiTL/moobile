# 一条能力该写在哪：库 / 生成器 / 应用

主文档（`SKILL.md`）是**门禁**（最贵的几条上桌）；本文件是它的**细则** —— 按主题展开，按需读。

## 一、三个问题，**顺序不能反**

1. **它在源码里有没有答案？** 有 ⇒ **生成器**（只有它手上有源项目的 CSS / 选择器 / 祖先链）。
   没有 ⇒ 看后两级。
2. **它对所有应用都成立吗？** 成立 ⇒ **库**。只对这个应用成立 ⇒ **应用**。
3. **认错了会不会静默出错？** 会 ⇒ 宁可**点名**（进迁移报告的 TODO），不要猜。

## 二、每一层收什么

| 归宿 | 收的是 | 能进的正例 | 不许进的反例 |
|---|---|---|---|
| **库** | 机制：与源项目无关、不做就是错的 | 文字默认样式与"最近一层文字上下文"（`render.mbt`）；`style/`；能力注册（`npm/moobile-host/core.js`） | 沿祖先链按 CSS 规则合成样式 —— 库没有源 CSS 的祖先链，实测猜错两次；具体列宽、具体字体名 |
| **生成器** | 语义：要源项目的信息才对，规则仍通用 | CSS→`@style` 逐条映射、`line-height` 无单位=倍数、`display:grid` 降级、祖先链展开（`npm/moobile-host/lib/migrate/`） | 精度不足的规则（实测"空链即网格子项"精度 1/8 ⇒ 删掉、改成点名）；`@media` 里的具体值 |
| **应用** | 意图：机械迁移**注定**认不出来 | `set_text_style_of(@styles.page())` 的**调用点**；断点→Model；业务状态；`verify.mjs` 的判据本身 | 业务语义、设计决策塞进库 |

## 三、这一层决定你必须跑哪几条门
